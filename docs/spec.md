# Crosspost spec

## Goal

Write a post once, then publish it to several social platforms with as little copying and retyping as possible. Priorities: free, convenient, no risk of account bans, and nothing private stored anywhere but the user's own browser.

## Hosting

- A static site on GitHub Pages at `/crosspost`. No server, no API routes, no accounts or tokens.
- Drafts and preferences live in the browser's localStorage (keys start with `crosspost:`), so they stay on that device.
- A GitHub Actions workflow builds the static export (`out/`) and deploys it on every push to `main`.

## Stack

- Next.js 16 (App Router, `output: "export"`) and TypeScript.
- Tailwind v4 with shadcn/ui (style new-york, base color neutral, lucide icons, sonner toasts). Add components with `bunx shadcn@3.8.5 add`.
- Bun as the package manager. vitest for unit tests. dnd-kit for reordering.
- Cross-platform scripts only (Windows and POSIX).

## Platforms

Every platform is posted by hand: Crosspost shows the text per post with a Copy button, and an Open button that opens the platform, prefilled where the platform allows it.

| Platform | Limit and counting | Long posts | Open button |
| --- | --- | --- | --- |
| Bluesky | 300 graphemes (an emoji is 1) | Split into posts | Prefilled: `https://bsky.app/intent/compose?text=…` |
| Threads | 500; emoji count as their UTF-8 bytes (per Meta's docs); at most 5 links | Split into posts | Prefilled: `https://www.threads.com/intent/post?text=…` |
| LinkedIn | 3,000 | No threads: warn and require shortening | Prefilled: `https://www.linkedin.com/feed/?shareActive=true&text=…` (undocumented) |
| X (Twitter) | 280 weighted (see below) | Split into posts | Prefilled: `https://x.com/intent/post?text=…` |
| Facebook | 63,206 | n/a | Opens Facebook; Facebook forbids prefilled text |
| Instagram | 2,200; at most 30 hashtags | n/a | Opens Instagram; the photo or video is added there |
| Mastodon (hidden by default) | 500 on most servers; graphemes, links with a scheme as 23, mentions as @name only | Split into posts | Prefilled on the user's server: `https://<server>/share?text=…` |

### Platform notes

**Bluesky:** shows a "1/2" pill on thread posts itself, so Crosspost's " i/n" label is off by default for Bluesky, with an "Add 1/n anyway" switch on its card.

**Threads:** Meta's docs confirm emoji count as their UTF-8 byte length, and posts with more than 5 unique links are rejected; the card flags that.

**LinkedIn:** no threading, so a post over 3,000 shows a warning instead of splitting.

**Threads:** its mark is black, so the UI uses a neutral gray, `oklch(0.66 0 0)`, near the other brand colors' OKLCH lightness (0.52 to 0.68), so it sits level with them in both themes.

**X / Twitter:** two entries for the same service: "X" with the X logo (shown by default; it's the platform's name) and "Twitter" with the classic bird (hidden until switched on in Settings, a nod for anyone who prefers the old name). Both post through X's intent link and count the same way. Counting uses twitter-text v3 weighting: code points in 0–4351, 8192–8205, 8208–8223 and 8242–8247 weigh 1, all others 2; an emoji sequence weighs 2; every URL weighs 23, bare domains included; NFC-normalize first.

**Facebook:** breakpoints shown on the card (unofficial, widely reported): "Background color" (Facebook's name for colored-background text posts) up to ~130 characters and only without links; "See more" after ~480 on desktop.

**Instagram:** caption only, links aren't clickable, and the feed cuts captions at ~125 characters ("more").

**Mastodon:** counting follows Mastodon's own `StatusLengthValidator`: grapheme clusters, after each http(s) link becomes 23 characters and each `@name@server` mention becomes `@name` (bare domains aren't links there, so they count in full). Servers can raise the 500 limit; Crosspost uses 500. Hidden until shown in Settings, where the user can enter their server (a host, URL or handle all work); empty or unreadable means mastodon.social.

### Phone apps and the share sheet

On a phone the share sheet is the one route that moves a post's text and all its images in one go: a web page can put one item on the clipboard and one file in a drag, and the apps' composers don't all take a pasted image. So each post on each card has a Share button (where the browser has a share sheet) that hands the text and that post's images to it through the Web Share API, and the platform's app takes what it takes. What each app keeps, as far as it's known (checked on a phone: none yet; the sources are the apps' code or developer reports):

| Platform | From the share sheet | How sure |
| --- | --- | --- |
| Bluesky | Android: text and images together (up to 10). iOS: the extension handles the first attachment's kind only (text, link, images or a video), so with images along the text is dropped; Share puts it on the clipboard for that. | Its source: `modules/Share-with-Bluesky/ShareViewController.swift` and the share extension PR (bluesky-social/social-app#2587). |
| Threads | Text or a link, and images (its iOS extension is built on Instagram's). Whether text and images arrive together isn't confirmed. | Closed source; reported. The card asks to check both arrived. |
| X (Twitter) | Text, links and images, 4 at most as in its composer ("Post to X"). | Closed source; widely reported, unverified. The card asks to check both arrived. |
| Mastodon | Android: text and media together. iOS: the extension accepts text, one link and up to 4 images (or 1 video); whether text and images arrive together isn't confirmed. | Its source: `ShareActionExtension/Info.plist` in mastodon/mastodon-ios, and the `SEND` and `SEND_MULTIPLE` filters on `*/*` in mastodon/mastodon-android. |
| LinkedIn | A link or text, and images; whether it keeps the text with several images isn't known. | Unverified; the card asks to check both arrived. |
| Facebook | Images only. Meta's sharing docs forbid prefilling a post, and the app drops shared text, so Share copies the text to the clipboard first. | Policy from Meta's iOS sharing docs; the dropping reported by developers. |
| Instagram | One image and no caption. Its extension takes a single image, so Share sends the first image of the post and copies the caption; the rest are added in the app. | Developer reports, old ones, so worth a check. |

Each adapter carries this as `share` (`note` for the card, `dropsText` for Meta's apps, `maxImages` for Instagram). What else to know:

- **Threads of more than one post:** the share sheet always opens a new post, so share the first post, then add the rest in the app's composer with Copy per post (Bluesky, X and Threads hold a whole thread before Post; Mastodon needs a reply per post).
- **Sharing out** (`navigator.share` with files): Chrome, Edge and Safari on Windows, macOS, Android and iOS (Safari from iOS 15); never Firefox. Chromium takes at most 10 files and 50 MB in all, refuses HEIC, and shares no files in Incognito. Share converts anything but JPEG, PNG and GIF to PNG first (X's own share target lists only those, with video; a format one app won't take would fail the whole share) and puts the text on the clipboard whenever images go along, so an app that keeps only the images still gets the text by paste. Without a share sheet, or when the browser can't send the images along (`navigator.canShare` says), the card falls back to Copy and Open, and Share sends the text alone with a note.
- **Sharing in** (the share target): installed web apps join the share sheet on Android (Chrome, installed as a WebAPK; Samsung Internet), on ChromeOS, and on Windows through Edge. Chrome on Windows and macOS, Safari everywhere and Firefox don't register them, so there the sheet never offers Crosspost. On an iPhone the way in is to copy the text and paste it in Compose, and to pick the images from Photos.
- **The platforms' own share targets** (for the desktop, where there's no app): x.com's web app takes files (POST, multipart: title, text, url, files), Mastodon's takes title, text and url only (GET), Instagram, Facebook and LinkedIn declare none, and Threads and Bluesky serve no manifest. So the one desktop path that moves text and images in one go is Windows with x.com installed as an Edge app; untested.
- **Open prefilled on a phone:** the intent links open in the browser; the apps may claim them (Bluesky, X and Threads register their domains), in which case they open the app's composer with the text, without the images.

## Features

- **Compose box** with a character count, saved as you type.
- **A card per platform:** brand logo (cards, rail tiles and split chips all take the app's own border and surface; brand tints made gray marks like Threads and X look switched off and pink ones like Instagram look like errors), a posted check, counter (amber near the limit, red over), a "?" tooltip with the counting rule, breakpoints where relevant, and the posts with their buttons.
- **Splitting:** paragraphs, then lines, then sentences (`Intl.Segmenter`), then words; inside a word only as a last resort; URLs stay whole when they fit. A unit that has to be broken starts a new post. Optional " i/n" numbering reserves room for the label. Compose's "Number posts" switch (off by default) shows each platform it covers as its mark in a brand-color circle. Bluesky shows a post's place in a thread itself, so it's left out of Compose's switch.
- **Split markers:** a caret and logo flag where each threading platform's next post starts. Drag a flag to move a split; drag one out of the text, or well below its last line (over a line and a half of empty box), to remove it, and while it would be removed the flag following the pointer is dimmed and destructive red; double-click to undo a manual one. A scissors handle moves splits shared by several platforms together; while a group is dragged, its flags show beside the tag in the text, and outside the text the scissors go with the flags on the pointer (red, like them, when letting go would remove the group). Wherever two or more platforms split at the same spot (an All split, including after some were dragged off on their own), the caret and tag take the All chip's neutral color, the tag shows the scissors and post number ("✂ 2"), and the platform flags stay hidden until the tag is hovered or focused, so one can be dragged off. Flags in the group carry no number unless theirs differs from the tag's. Splits before the drop point stay put; the rest reflow. Manual splits follow the text as it's edited. Placed markers rest at 80% opacity, so the text behind shows through, and go to full while hovered or focused. A card whose splits were moved by hand offers Auto Split (back to fitting the limit); when Compose's shared splits (the hand-placed ones most of the other threading platforms have, as an All split leaves them) differ from the card's, it also offers Revert, including right after Auto Split.
- **Split chips** in the Compose header, after a "Drag to split" label (All plus one per threading platform): drag one into the text to add a split, or click to split at the cursor. Neither the chips nor the markers in the text have hover cards.
- **Theme switch:** the new theme blooms out from the page's blue glow (lower right of the content) over the old one, a soft-edged circle growing over 900ms until it covers the window, so the gradient, background and cards all tween across. A view transition; browsers without them, or with reduced motion, switch at once.
- **Colors:** platform brand colors are for logos only (and the split flags built around them); counts, badges, checks, highlights and switches use the app's blue.
- **Status rail:** in the phone-width row, a Compose button (a pencil, as beside Compose's heading) comes first: it scrolls to the top, where Compose is, and focuses its text box; the side column sits beside Compose, so it has none. Tiles are 36px with 6px gaps in that row (40px in the column), so Compose, the default platforms and More fit on one line on a phone; when the platforms need more than one line, the lines are balanced (8 tiles as 4 and 4, not 7 and 1). A tile per platform with its post count once the post splits; a red ring and warning badge when something needs attention (over the limit, too many links or hashtags). Click to jump to the card; drag to reorder platforms, and the cards reorder live to match while the tile moves, gliding to their new places with the tiles' own timing (250ms ease; none with reduced motion), with the dragged platform's card scrolled into view (Escape puts them back). As in the introduction's list, the tiles come in two parts: the platforms posted to, then a line marked Off, then the ones turned off, grayed (a short upright line in the phone-width row). The second part opens while a tile is dragged, growing into place (300ms), and closes again after the drop. A small More at the end of the rail (as wide as a tile, shorter) opens it too, with a legend of what the tiles do ("CLICK / GO TO", "DRAG / ORDER", between a line above and below; side column only; More and Less lettered like the legend's gestures), so a platform that's off can be dragged back up: hovering More opens it after 200ms (a tap on touch screens), and More moves below everything it opened, reading Less. Less closes it, and so does 5 seconds with no activity on the rail: any hover, pointer movement, focus or drag there starts the count over, and it runs only once the pointer (or keyboard focus) is away and no drag is going, so a drag let go off the rail counts from the drop. On touch screens only Less closes it. A tile is outlined in the warning color (amber) only when its platform differs from Compose on its card: splits that differ from Compose's (platforms that don't split have none to differ), edited post text, or its own image layout. Its post count stays the app's blue. An outlined tile's tooltip adds the count on a line of its own ("Bluesky: 2 posts", then "1 override"): one for splits that differ from Compose's, one per post edited on the card, one for its own image order, and one per image moved on that platform alone. Tiles move during a drag but never scale (dnd-kit's sorting would size them to their neighbors, stretching the ones beside the line). Dragging a tile across the line turns its platform off (with Undo in the toast) or back on, at the place it's let go; at least one stays on. The rail and Settings' platform list share the same platform settings, so each shows what the other changes. The dragged tile is a copy fixed to the window under the pointer, with a faint placeholder where it will land; the rail is sticky, so dnd-kit's scroll compensation is bypassed (tiles are measured where they sit, for the pointer and the keyboard alike) and the page never auto-scrolls during the drag, only to bring the card into view. A turned-off tile's tooltip says only "Name: currently off". Tile tooltips open to the right in the side column, away from the cards, and flip left when the window has no room; in the phone-width row they open above the tile.
- **Settings** (gear to the right of the theme toggle): choose which platforms to show, sorted by name (A to Z first), popularity (rough monthly users, shown beside each; most first) or launch date (year shown; oldest first), with a direction toggle, and the server for platforms that need one (Mastodon: an "Opens to server" field, mastodon.social when empty, with a Tab key cap in the field while Tab would fill that in). Hidden platforms leave the cards, the split chips and the numbering circles (the rail keeps them under its Off line), and keep their place in the order for when they come back. At least one stays shown. Stored in `crosspost:platforms`, shared by the header and composer and synced across tabs. At the bottom, Clear Data (see below) is the one way back to the defaults.
- **Introduction** (help button, left of the theme toggle): a dialog in three steps: Draft (what the app does), Decide (what's in your hands) and Deliver (the last steps, yours). It opens by itself on a first visit (`crosspost:intro-seen` marks it seen on close) and focuses Compose when it closes; Compose skips its autofocus until then, so it can't take focus from the dialog. It sits at a fixed spot near the top of the window rather than centered, so its header never moves: the steps as stops on a winding dotted trail (a nod to the signpost), a timeline of the introduction: a small fingerpost board plays along the curve in time, inking the way behind it. The introduction plays through by itself: each step is the stretch up to the next stop, and moves on when its drawing ends. On Draft each tab's share of the stretch is its drawing's length (timed by how long the last pass took; Draft's drawings play 40% slower than their scripts' timings, so each beat lingers), so the marker keeps one pace, and it reaches Decide's stop as the last tab ends; on Decide it runs on to Deliver's stop as Decide's drawing plays, and Deliver, at the end, stays. Next, Back, the arrow keys or a stop's name (each stop shows its icon over its name) glide the marker to the new place. The track can be dragged like a timeline: the pointer needn't stay on it, as the marker takes the point of the curve level with the pointer, left to right; the step and Draft's tab follow as it passes them (past 95% is Deliver), and it plays on from where it's let go, with Back on the left and Next and Skip on the right. The trail and its labels sit in the same place on every step: the header is a grid with fixed-width button columns, Back keeps its space while hidden on the first step, and on the last step Skip becomes a Start button as wide as Next and Skip together. Next and Start are primary; Back and Skip are secondary. Skip and Start both close the introduction into Compose. At phone width the trail takes its own row with the buttons under it. The steps follow the Figma panels, with every step's title in the muted color. Draft and Deliver each have a framed visual (320px tall), the drawing scaled up or down to fill it with a small margin; a note (Images') adds a strip below that. Draft puts its tabs and its title (centered, with no caption) above the visual. Decide and Deliver line up the same way: the title and a short text along the left edge at the top, Decide's drawing (its list) to the right of them, Deliver's under them. The body scrolls under the header only when it runs past the window (thin scrollbar). **Draft** has Write, Split and Images tabs (80px each) above its visual, and in place of a caption each tab's own title, in the muted color: "Write once, preview everywhere", "Easily drag or insert split markers in posts" (which changes to "Drag markers out to remove" as Split's drawing moves on to removing them) and "Preview and stage images". Each moves on to the next when its drawing ends, and Images on to Decide, until a tab is picked (then that tab's drawing loops). The three drawings share one sample and one Compose, so each ends where the next begins: Write types the sample in, Split works its splits on it and leaves it as it found it, and Images adds pictures to it. The sample (284 characters) is one only X splits on its own (at its third sentence), with Bluesky near its limit. Compose is laid out as the app's and the same on every tab: the title with the Drag to split chips, the text box, Number posts and the character count, then the image area (Clear Post and the drop bar). Its split markers show as in Compose, X's own included. Draft's canvas (520 by 264) is just tall enough for Compose, so the drawing fills its frame; on Images, as the tile row opens, the canvas grows to 340 and the drawing zooms out to fit it, like a camera pulling back, with Compose pinned at the top. The chips are dimmed except on Split, where they fade up and stay lit through its loops; moving on from Split to Images, they start lit and fade back down. Write types the sample in: Bluesky's count turns amber near its limit, and once the text passes X's limit, X shows 2 posts and its split marker appears in the text. Split starts from there, with X's marker showing, and each gesture works as Compose does: it drags the All chip down into the text (outside the text the scissors and the three flags ride on the pointer with a plus; over it, the All tag itself snaps word to word under the pointer, flags showing) and lets go at the second sentence, which starts post 2 everywhere (and takes over X's own split); clicks later in the text, so the caret shows there, then the Bluesky chip, which puts Bluesky's own blue flag at the caret; then drags Bluesky's flag, and then the All tag, straight down to just past a line and a half below the last line (where Compose removes a split; the All tag snaps through the lines below it on the way), each turning into a dimmed red copy with a cross on the pointer once letting go would remove it. At rest the All tag shows only the scissors and post number, trimmed to the figures, with its flags tucked away; they come out while the pointer rests on the tag (as on hover in Compose) or holds it. Images drags files in from outside the page: Compose's drop bar opens up across the image row's place ("Add 3 images") with a glow spreading from where the files came in, and they land as tiles with the add slot after them, and on X's first post. A full-size blue note in a strip along the bottom of the frame, under the drawing, reads "Images stay in your browser, never uploaded directly." **Decide** ("Pick your destinations") is a drawing of the platform list on the right, with the title, its text and a note to its left: a column of tiles like the rail's (176px wide; 30px tiles with 18px logos and 14px names), each with its name, under Post to and, below a line, Off, both in order by name. A drawn pointer (a finger on touch screens) drags Twitter up out of Off and lets it go just over the line; it settles into its place by name, between Threads and X, and the line and Off move down to make room. Then it drags X down into Off, where it settles after Mastodon. It's a demonstration with its own list: it doesn't read or change the app's platform settings (the order is still kept with them in `crosspost:platforms`, where the rail sets it; it used to live in `crosspost:prefs`, which is read once to carry it over). Each piece is checked off on the card as it's copied (the image checks, the Copy button's done state), and once all four are, the card's Posted mark in its upper right fills in; on a touch screen, a phone that copies an image, opens the app, long-presses to paste, and posts. The drawings (src/components/intro-art.tsx, and Decide's in src/components/intro-decide.tsx) are fixed canvases (520 by 260 on Deliver, 300 by 260 for the phone; Draft's 520 by 264, growing to 340 on Images), zoomed to fit, with text as ghost words (a bar the width of each word of the Lorem Ipsum sample) and hand pointers drawn as single filled outlines; under reduced motion each holds one frame.
- **Image staging:** up to 10 images, shown under Compose: 4 across at the largest size, 5 across once there are five tiles (images plus the add tile), and past five a second line; where Compose is too narrow for five (under 32rem), 4 across. A single post on Bluesky, X or Mastodon takes 4 (the adapter's `maxImages`; Threads, LinkedIn, Instagram and Facebook take at least 10): when one of their posts holds more, the card says so in red, with the fix (move the extras to another post, or leave them off there), and its rail tile shows the warning badge. With none staged, a slim drop bar sits beside Clear Post; while an image is dragged over the page it moves up and left into the full-width spot the image row takes, and slides back when the images are cleared. While dragging, the drop targets say how many images the drag holds and how many will fit (Chrome and Firefox report this; Safari doesn't). Drop or paste them anywhere on the page (no field needs focus), or pick them; extras are left out with a note. While an image is dragged over the page, a soft radial glow spreads across the drop zone from where the drag entered the window, and recedes toward where it left. Images are kept in this browser's IndexedDB, never uploaded. Each can be copied (as PNG, to paste into a composer), dragged, downloaded or removed (the x turns red; a second click removes), and each card shows them on its first post (click to copy, or drag it out of the page and drop it somewhere that takes it, such as the platform's composer in another window or the other side of a split view, which checks it the same way; numbers sit lower left; copied ones turn gray with a blue check badge on the lower right (it turns red on hover; a click clears it); a hover x over the top-right corner turns red on the first click and leaves the image off that platform only on the second, with "Show N hidden" to bring it back). On threaded platforms (Bluesky, Threads, X), images go with the first post unless dragged onto another post. A move mirrors to all three threaded platforms by post number; with Ctrl (Cmd on a Mac) held on drop, it applies to that card only. Any post on the card takes the drop; while one is dragged, the other posts show a full-width "Move here" row in two fixed lines: "Move here", then "On all threads / <Platform> only" with a Ctrl key cap (⌘ on a Mac), the choice in effect in bold. Dragging the page's own images never stages them again. Image order follows the Compose tray (drag a tile beside another to reorder; a line marks where it lands). Dragging a card thumbnail beside another gives that platform its own order, with "Match Compose order" to go back; dropped beside an image in another post, it moves there too. Once any card has moved or reordered images, a Reset Image(s) button (with the confirm step and Undo) puts every card back on the tray's order with all images on the first post. Instagram's card notes that it needs one.
- **Post buttons:** the first post has Open Prefilled (labeled); every post has Edit and Copy as icons, their names in a hover card below. Copy turns into a blue check on a blue tint once used (a finished task, still clickable) and stays that way across reloads until the post's text changes.
- **Posted marks:** a check icon in each card's header (its tooltip counts the steps: "Step 2 of 4", one for each post and each image still on the card); clicked, it fills with the app's blue ("Post Complete!"), the card dims a little, and its rail tile shows a blue check in place of the post count. Once every post and every image still on a card has been copied (or shared; opening a post prefilled counts as copying it), the platform marks itself posted, with a toast and Undo; it never unmarks itself. Cards have no switch of their own: a platform is off when it's in the rail's Off part. Progress (posted marks, copied posts and images, images left off a card) is kept in `crosspost:progress`.
- **Edit a post:** Edit opens a post as a text box in place. Once its text differs from what Compose gives, the whole post turns orange (the box inside drops its own outline) and Edit becomes an orange undo icon ("Reset to Compose", with Undo in the toast); typing it back to Compose's text drops the edit. Edits are kept per platform by post number (`crosspost:post-edits`), with a note when Compose has changed since. Counts, problems, Copy, Share and Open Prefilled use the edited text.
- **Hand-moved splits:** a card whose splits were moved by hand shows a dashed bar in the app's blue with a scissors and the post count ("3 posts"), then Revert (undo-dot icon: back to Compose's shared splits, shown only where this card's differ) and, at the right end since it's there whenever splits were placed by hand, Auto Split (rotate icon: the hand-placed splits go and the platform's limit decides, so a post still over the limit keeps its automatic splits). The count is in posts, as everywhere else. Each post that starts at a hand-placed split has a scissors before its number.
- **Clear Data** (Settings, at the bottom: "Removes and resets everything saved in this browser. There is no remote data." The button asks "Confirm?" before it acts): removes everything Crosspost keeps in this browser, the post and the settings included, so it also stands in for a reset of the settings: every `crosspost:` key in localStorage and sessionStorage, the image database and the offline cache; the theme goes back to dark and the page reloads as on a first visit. Only Crosspost's own keys go, since the site shares its origin with others on the same host.
- **Tray tiles:** at rest a tile shows only its number (lower left). Images have no hover card (a file name says little, and a pasted image's is made up; it's kept only for downloads and sharing); hovering ALT shows the alt text. On hover or focus, or after a tap on touch screens (a tap elsewhere hides them): ALT upper left (blue once the image has alt text), the crop pencil and the remove x upper right, Download and Copy lower right (no Download on touch screens). On narrower tiles (five across, under 7rem) Download goes and the crop pencil moves under ALT; on the narrowest (phones, under 5.5rem) the pencil goes too.
- **Alt text:** ALT opens a dialog laid out like Bluesky's: "Image 1 – Alt Text", the image across the whole panel, a text box with a count against Bluesky's 2,000 (graphemes; over it, Save is off), then a big Save with a small Cancel to its left (Ctrl or Cmd plus Enter saves). Stored with the image. On the cards, an image with alt text has a blue ALT button that copies the text, to paste into the platform's alt field, since the clipboard carries pixels only.
- **Crop:** the pencil opens a crop editor ("Image 1 – Crop"): the image with a white frame and thirds over it, the outside shaded; drag inside to move, a corner to resize (handles take the pointer a little beyond what's drawn, more on touch screens), or focus the frame and use the arrow keys to move it and Shift with the arrows to resize it; shapes Free, Original, Square, 4:5 and 16:9; the size in pixels; Reset, Cancel and Save. The crop is always taken from the image as it was added (kept with the image, with the frame), so it can be changed or undone later; JPEGs stay JPEG, others become PNG so transparency survives. A new crop clears that image's copied checks.
- **Tag check:** when a platform's posts hold @tags (`findMentions` in `src/lib/text.ts`), an amber notice reads "Check tags: @alice" directly above each post that holds them, since a handle can mean a different account, or nobody, on each platform, with a check-mark Confirm button. Each post's tags are confirmed on their own. Confirming is one of the card's steps (the Posted mark's "Step 2 of 4" counts it), and a platform marks itself posted only once its tags are confirmed too; confirmed, the notice becomes a quiet "Tags checked" line with Undo. A new tag needs confirming again. Kept with the progress (`checkedTags`).
- **Image layout saved:** where images go across a thread's posts and each card's own image order are kept across reloads (`crosspost:image-placement`, `crosspost:image-order`), like the rest of the progress.
- **Clear Post** and, with images staged, **Clear Image(s)** (left-aligned): the first click turns the button red and reads "Confirm"; the second clears, with Undo in the toast. Clear Post clears the draft, manual splits, images, post edits and progress.
- **Split-view reminder** (Chrome only): "External link > Right-click > Open link in split view", with an X ("Collapse Reminder") that shrinks it to an amber bulb button; the bulb ("Show Reminder") opens it again. Remembered in this browser (`crosspost:split-view-tip-closed`). Hidden at phone widths, where there's no split view to open links in (to revisit). Its background is opaque, so the page's blue glow doesn't show through.
- Dark grey theme by default, light/dark toggle. The page background is a radial gradient fixed to the window: a hint of the logo's blue (#40A8F8, OKLCH hue 246) at the center, easing out to the theme's background toward the edges; lighter than the background in dark mode, darker in light. A gray noise tile (SVG feTurbulence, contrast-stretched) sits over it: soft light at 35% in dark, multiply at 15% in light, where the gradient fades to an off-white so the grain has something to darken; on the dev server, ?lab opens a panel to tune it live (src/components/noise-lab.tsx, loaded through dev-tools.tsx so it never ships). The header's bottom edge and the Compose card's border (both 2px) run the other way, from that blue at 55% opacity at the upper left to the text box's border color with 20% of the blue on the right (`.brand-edge-b`, `.brand-edge`). Sticky header whose content lines up with the page's centered column, responsive down to phone width, scrollbar space always reserved. Hover hints use the styled tooltip (as on the footer links), never the browser's plain `title` tooltip.
- **Compose column (wide screens):** pinned below the header and at least the window's height, so the platform column's scrolling and height never move it. The text box takes up to 12rem of the room left in the window, shrinking with the window but never below its text (it grows with its text and never scrolls inside). When the column still doesn't fit (a short window or a long post), it has no scrollbar of its own: its pinned top moves up by the overflow, so the page scroll carries it until its bottom is in view, then it stays pinned. The editor measures this (fitToWindow in compose-editor.tsx). The page's bottom padding equals the column's gap to the window edge, since a pinned column can't reach past the end of its grid row.
- **Made by** footer: on wide screens at the bottom of the Compose column, its width, flush with the bottom of the window (the column is pinned and as tall as the window); on phone widths at the end of the page: the year, "Made by Taylor Wright", and icon links to the portfolio (redlamp.org), LinkedIn and this project on GitHub (github.com/redlamp/crosspost).
- **Installable app:** a web app manifest (`src/app/manifest.ts`, written to `/crosspost/manifest.webmanifest` and linked from `<head>`) with the name, `display: standalone`, the dark theme's background as theme and background color (`#1f1f1f`, oklch(0.24 0 0), in `src/lib/theme.ts`), and icons in `public/` rendered from `src/app/icon.svg` with sharp: transparent at 192 and 512 for "any", and "maskable" on the dark background with the mark inside the safe zone. A `theme-color` meta (the color a phone paints around the page) that the app shell keeps in step with the theme toggle (white in light), and Apple's home-screen tags with an opaque black status bar, so nothing needs safe-area padding. A service worker (`public/sw.js`, a plain file so its scope is `/crosspost/`; registered by `src/components/app-shell.tsx` in production builds only, since on the dev server it would hand out stale files) keeps the page on install and everything else as it's fetched, network first, so every visit is current and the installed app still opens offline. Chrome and Edge offer Install; Safari on iOS has Add to Home Screen. The manifest's and worker's paths carry the base path at build time (`BASE_PATH`, passed to the client as `NEXT_PUBLIC_BASE_PATH`).
- **Share target:** the manifest registers Crosspost as a share target: a POST with a form (title, text, url and image files), which the worker takes, since a static host can't. It keeps the share in IndexedDB (`crosspost-share`) and opens the app at `/?share-target`; the composer takes it once (`src/lib/share-target.ts`): the title, text and link, each once, fill the draft or join it on a new paragraph, the images go to the tray (up to 10, extras noted), and the toast has Undo. Android as an installed app, ChromeOS, and Windows through Edge: the other desktop browsers, Safari and Firefox don't offer installed web apps in their share sheets (see "Phone apps and the share sheet").
- **Share** (`src/components/share-button.tsx`, `src/lib/share.ts`): a button per post on every card where the browser has a share sheet, before Open and Copy. It calls `navigator.share` with the post's text and that post's images as files when the browser says they can go (anything but JPEG, PNG and GIF converted to PNG first), with the text put on the clipboard as well, within the tap, since some apps keep only the images; then it marks those images copied. For apps that drop shared text (Facebook, Instagram) it sends the images only, as many as the app takes (one for Instagram), and the toast says what to paste or add in the app. Backing out of the sheet does nothing; a failure suggests Copy. On touch screens a line under the posts says what the platform's app takes (the adapter's `share.note`); see "Phone apps and the share sheet".
- **Touch screens:** the tray's copy, download and remove buttons and the card thumbnails' x show without hover (`pointer-coarse:`), and the rail's row wraps once the platforms outgrow the width.
- **Share previews:** Open Graph and Twitter tags from `src/app/layout.tsx` (`metadataBase` is the origin alone; Next adds `/crosspost` to the image URL) and `src/app/opengraph-image.jpg` with its `.alt.txt`: 1200 by 630, under 100 KB, exported from the Dark Open Graph card in the Crosspost Figma file ("One post, every destination."). To change it, export that card again as a JPEG; after deploying, refresh the cached previews with LinkedIn Post Inspector and Facebook's Sharing Debugger.

## Architecture

- `src/lib/text.ts`: counters (graphemes, code points, UTF-8 length, Twitter weighting, Threads emoji counting), URL finder, splitter with manual breaks, break shifting on edits, word snapping.
- `src/lib/adapters/<platform>.ts`: one file per platform with `id`, `name`, `limit`, `count`, `chain`, `countNote`, `brand`, `open`, and optional `breakpoints`, `problems` and `numbersThreads`. Adding a platform means one adapter file plus one line in `adapters/index.ts`.
- Images are imported (not referenced from `/public`) so they work under the base path. The exceptions are the files the browser must fetch by a fixed address: the manifest's icons and the service worker, in `public/`, whose paths the manifest and the app shell build from `BASE_PATH`.
- `src/lib/share.ts` hands a post to the share sheet; `src/lib/share-target.ts` takes one shared in; `public/sw.js` is the worker between the share target and the page; `src/lib/theme.ts` holds the theme colors as hex for the manifest and the theme-color meta.

## Tests (vitest)

Counters (family emoji, flags, CJK, URLs as 23), URL finding (http, www, bare domains, trailing punctuation, emails and handles ignored), the splitter (fallback levels, URLs kept whole, numbering within the limit, hard splits, manual breaks), break shifting and word snapping, open links, the Threads and Instagram problem checks, the shared text a share target's title, text and link make (`sharedText`), and the service worker's share target (`public/sw.js` loaded into a sandbox with a stand-in IndexedDB: a shared form is kept with its images only and answered with a redirect to the flagged app address, at the root and under the base path).
